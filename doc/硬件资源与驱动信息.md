# 硬件资源与驱动信息

更新时间：2026-05-27

这个文件记录当前项目确认过的开发板、板载资源、外接模块、驱动组件和硬件风险。没有确认的引脚或参数只标记为待确认，不强行补全。

## 项目范围

第一版做一个单方向三模态行人入侵检测装置，先完成功能闭环：

```text
E54-24LD12C 雷达
    -> AM312 PIR
    -> OV5647 摄像头
    -> ESP32-P4 AI 判断
    -> 蜂鸣器 / LED 报警
    -> ESP32-C6 Wi-Fi 上传事件和 JPEG
```

第一版保留：

- ESP32-P4 主控。
- ESP32-C6 联网。
- 1 个毫米波雷达 `E54-24LD12C`。
- 1 个 PIR `AM312`。
- 1 个 OV5647 摄像头。
- 10.1 英寸微雪 DSI 屏幕。
- 边缘 AI 行人检测。
- Wi-Fi 上传事件和 JPEG 图片。
- 蜂鸣器 / 红色 LED 报警需求。

第一版不做：

- 4 路雷达或 4 路 PIR。
- 舵机 / 云台。
- 多方向检测、目标方位判断、自动转向或全向覆盖。
- 热成像。
- 全天候夜视优化。
- 超低功耗待机。

本地报警的需求已保留，但蜂鸣器、LED 的型号、GPIO、限流/驱动方式还没有确认。代码上先不接入报警组件；必须等视觉 AI 确认“是人”以后，才允许后续报警或点亮提示。

## P4 与 C6 联网架构

ESP32-P4 负责主业务、摄像头、图像处理、AI 推理、显示和状态机。ESP32-C6 作为网络协处理器，通过 SDIO 与 P4 通信，负责 Wi-Fi 6 和 BLE。

| SDIO 信号 | P4 GPIO |
|---|---:|
| SDIO_CLK | 18 |
| SDIO_CMD | 19 |
| SDIO_D0 | 14 |
| SDIO_D1 | 15 |
| SDIO_D2 | 16 |
| SDIO_D3 | 17 |
| C6_RESET | 54 |

推荐方向：

- P4 侧使用 `esp_wifi_remote`。
- P4/C6 通信使用 `esp_hosted`。
- 应用层尽量继续使用标准 `esp_wifi` API，把 C6 当作网络协处理器看待。

- 用户本地编译已通过，但还未记录真实硬件点亮和摄像头画面显示结果。

## 摄像头

| 项目 | 信息 |
|---|---|
| 型号 | RPi Camera (B) |
| 传感器 | OV5647 |
| IR-CUT | 旧需求文档记录为“无 IR-CUT”，实物仍需最终确认 |
| 像素 | 5 MP |
| 最大分辨率 | 2592 x 1944 |
| 接口 | MIPI CSI 2-lane，15-pin FFC |
| 输出格式 | RAW8 / RAW10 Bayer |
| SCCB/I2C 地址 | `0x36` |
| 可用组件 | `espressif/esp_cam_sensor` v2.1.0+ |
| 推荐方向 | `espressif/esp-video-components`，优先走 V4L2 API |
| 官方参考例程 | `examples/peripherals/camera/mipi_isp_dsi` |

当前目标不是一步跳到 AI，而是先形成摄像头到屏幕的显示链路：

```text
sensor -> CSI -> ISP -> PSRAM buffer -> DSI -> LCD panel
```

已知风险：`esp_cam_ctlr_receive()` 第二次调用可能卡死。后续接入摄像头时，优先研究 `esp-video-components` 的 V4L2 路线。

## PIR

| 项目 | 信息 |
|---|---|
| 型号 | AM312 |
| 类型 | 小型 PIR 人体红外传感器 |
| 项目作用 | 第二层确认，减少雷达单独触发造成的误判 |
| 常见模块工作电压 | 2.7 V 到 12 V |
| 传感器本体资料电压 | 常见资料也有 2.7 V 到 3.3 V 版本 |
| 静态功耗 | 常见模块资料标称小于 0.1 mA |
| 输出逻辑 | 检测到人体活动时输出高电平，未触发时输出低电平 |
| 延迟时间 | 常见模块约 2 s |
| 阻塞时间 | 常见模块约 2 s |
| 触发方式 | 可重复触发 |
| 感应范围 | 常见模块约 100 度锥角，约 3 m 到 5 m，受透镜影响 |
| 工作温度 | 常见模块资料为 -20 到 60 摄氏度；部分传感器资料为 -20 到 85 摄氏度 |
| 常见模块尺寸 | 约 10 mm x 8 mm |

注意：AM312 的资料存在“裸传感器”和“成品模块”口径差异。接 ESP32-P4 GPIO 时，信号电平不能超过 3.3 V，需要以后用万用表或示波器确认当前手头模块的输出高电平。

## 当前代码中的临时引脚

| 模块 | 当前代码引脚 | 文件 |
|---|---:|---|
| 雷达 | GPIO15 | `components/radar/radar.c` |
| PIR | GPIO16 | `components/pir/pir.c` |

重要风险：GPIO15 和 GPIO16 同时也是 P4 到 C6 的 SDIO_D1、SDIO_D2。只做 GPIO 学习时可以临时理解代码结构，但后续一旦接入 Wi-Fi / `esp_wifi_remote`，这两个引脚必须释放并重新分配传感器 GPIO。
