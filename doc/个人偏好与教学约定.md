# 个人偏好与教学约定

更新时间：2026-05-27

这个文件记录本项目里长期遵守的代码风格、命名习惯、资料判断方式和教学方式。它不记录具体进度；当前状态看 `学习进度与搁置问题.md`，硬件和外设信息看 `硬件资源与驱动信息.md`。

## 项目定位

- 这是一个带学习性质的 ESP32-P4 项目，不是单纯为了尽快堆出功能。
- 目标是借助项目逐步学习 FreeRTOS、ESP-IDF、ESP32-P4、外设驱动、摄像头、屏幕、AI 视觉和联网。
- 默认先把一个小闭环讲通、做通，再进入下一个模块。
- 默认不要帮我编译、烧录或监视串口，除非我明确要求。
- 遇到未知点时，优先把概念讲清楚，再决定是否写代码。

## 资料与实现原则

- 使用 ESP-IDF v6.0.1 的当前 API，避免使用已经废弃的 legacy API。
- 不编造未确认的硬件事实、引脚、时序、颜色格式、lane 配置、panel 初始化命令或 ISP 参数。
- 缺少关键事实时必须先说明缺口，必要时询问，不能靠猜把文档或代码补满。
- 复杂外设优先查 ESP-IDF 官方组件、官方例程、Waveshare 组件、Waveshare 例程和 ESP Component Registry 中已有组件。
- 当实现需要写大量复杂代码时，先判断是否已有组件或例程负责这部分复杂度。
- 第一版代码可以保守地拼出完整链路，但必须承认隐藏封装和未知硬件信息可能需要后续根据日志继续修。
- 修改 ESP-IDF 项目代码前，尽量说明组件来源、API 来源、宏定义来源，以及它们在链路中的位置。

## 代码偏好

- API 暴露保持简洁；没有必要给外部调用的函数，不拆出来做 public API。
- 简短逻辑如果放在当前位置更清楚，就不要为了“看起来高级”单独包装成函数。
- `main.c` 更偏向做初始化和流程编排，具体外设逻辑放在对应组件里。
- C 代码优先使用 Allman 风格大括号。
- ESP-IDF 返回值优先用 `ESP_ERROR_CHECK()`、`ESP_RETURN_ON_ERROR()` 等方式处理。
- 日志使用 `ESP_LOGI()`、`ESP_LOGW()`、`ESP_LOGE()`，不要用 `printf()` 作为主要调试方式。
- 注释要解释“为什么这样组织”，不要写“给变量赋值”这类没有信息量的注释。

## 命名偏好

- 标识符优先使用英文 `snake_case`，不使用拼音缩写。
- GPIO 常量使用 `XXX_GPIO`，例如 `RADAR_GPIO`、`PIR_GPIO`。
- FreeRTOS 任务函数使用 `xxx_task`，任务句柄使用 `xxx_task_handle`。
- 中断函数使用 `xxx_isr_handler`。
- 布尔函数使用 `xxx_is_active()`、`xxx_is_ready()` 这类能直接读出真假含义的名字。
- 模块内部状态变量后续优先使用 `s_` 前缀，例如 `s_main_task_handle`，便于区分文件内私有状态。
- 已经写好的学习代码不为了命名洁癖大面积重命名；只有当重命名能帮助理解结构时再改。

## 教学方式偏好

- 代码部分不要采用苏格拉底式反问法；请直接说明应该写在哪里、写什么、为什么这样写。
- 理论部分可以适当使用苏格拉底式问题，但要少而准，用来引导我建立概念，不要连续追问。
- 未知概念要讲得通俗、条理清晰，但不用烂大街的比喻。
- 讲新概念时，优先按这个顺序：
  1. 先说明它在 Keil/裸机开发里大概对应什么位置。
  2. 再说明 ESP-IDF / FreeRTOS 为什么需要这个概念。
  3. 然后说明它在当前项目里怎么用。
  4. 最后给最小伪代码或小片段。
- 当我说“不懂”“为什么”“这个 API 怎么用”时，优先使用：
  1. 我已经做对的地方。
  2. 我还没熟的是哪类能力。
  3. 这一小步现在应该怎么补。
- 如果我正在学代码，不要一次性给很大的完整工程；优先给一个能观察到现象的小闭环。
- 回复中的数学公式、角标和下标必须使用 LaTeX，例如 `$f_{pclk}$`、`$H_{active} \times V_{active}$`，不用纯文字硬写。

## Vision 链路讲解方式

- 讲完整链路时，把链路拆成小段，例如 sensor/CSI、CSI frame buffer、ISP、PSRAM buffer、DSI panel、LCD refresh。
- 讲每一小段时，同时覆盖理论、代码、API、宏定义、组件来源，以及前后代码关系。
- 触及尚未讲解的后续代码时，只做必要预告，不提前展开太多。
- 颜色错误、方向错误、重启等现象必须先回到数据格式、panel 配置、buffer 和日志，不直接大改代码。

## 当前项目优先级

- 已完成 GPIO 输入、中断、任务通知和最小状态机的小闭环。
- 当前重点转入 DSI 屏幕、OV5647 摄像头、CSI、ISP 和 frame buffer 链路。
- AI 推理、报警、联网、上传放在摄像头到屏幕闭环之后。
- 低功耗属于第二版内容。
- 如果某个高级模块卡住，允许先搁置并记录原因，不强行硬冲。
